# ws2812 —— PWM + DMA 驱动 WS2812B

## 实验目的

WS2812B 是单总线、归零码（NZR）的智能灯珠，**每一位的宽度只有 1.25 µs，高电平容差 ±150 ns**。这种时序靠软件延时（`HAL_Delay` / `for` 空转）根本做不到，所以本实验用「定时器 PWM + DMA」让硬件自动产生波形：**CCR 值就是高电平宽度**，DMA 把一串 CCR 值依次喂给定时器，硬件逐位输出。

## 硬件连接

| 信号 | 引脚 | 说明 |
|---|---|---|
| 数据 | `PB4` (TIM3_CH1) | 接灯带 DIN |
| 电源 | — | 灯带接 5 V，与 MCU **共地**；建议 DIN 串 330 Ω，首颗灯前并 100 µF |

## 关键配置

| 项目 | 值 | 说明 |
|---|---|---|
| `PSC` | 0 | 定时器直接跑 72 MHz，**1 个计数 = 13.9 ns** |
| `ARR` | 90 - 1 | 72 MHz / 90 = **800 kHz**，每位 1.25 µs |
| 通道 | TIM3_CH1，PWM1 模式 | 输出比较决定高电平宽度 |
| DMA | DMA1_Channel6（TIM3_CH1） | 内存 → 外设，**半字**对齐，Normal 模式 |

## 码元取值

| 码元 | 常量 | CCR | 高电平时间 | 规范值 |
|---|---|---|---|---|
| 逻辑 0 | `Code0` = 30 | 30 | 30 × 13.9 ns ≈ **0.42 µs** | 0.4 µs ±150 ns |
| 逻辑 1 | `Code1` = 60 | 60 | 60 × 13.9 ns ≈ **0.83 µs** | 0.8 µs ±150 ns |
| 复位 | `CodeRest` = 0 | 0 | 一直低电平 | > 50 µs |

`Code0 ≈ ARR × 0.33`、`Code1 ≈ ARR × 0.67`——改 `ARR` 时必须按这个比例同步改这两个常量，否则灯不亮或颜色错乱。

## 数据组织

WS2812B 每颗灯 24 bit，顺序是 **G-R-B**（高位先出）。代码里手写了一个静态数组，共 `96 + 1 = 97` 个元素：

```
每颗灯 24 个码元： [8×Code0] [8×Code1] [8×Code0]   → G=0x00, R=0xFF, B=0x00 → 红色
4 颗灯 = 96 个码元，最后跟 1 个 CodeRest（复位）
```

所以现象是 4 颗灯全亮红色。

## 程序流程

```c
ws2812_Update();   // 只在 main 里调用一次

void ws2812_Update() {
    static uint16_t date[] = { /* 96 个码元 + CodeRest */ };
    HAL_TIM_PWM_Start_DMA(&htim3, TIM_CHANNEL_1,
                          (uint32_t*)date, sizeof(date)/sizeof(uint16_t));
}
```

`HAL_TIM_PWM_Start_DMA` 会把数组里的每个值搬运到 `TIM3->CCR1`，每搬一个就产生一个 PWM 周期，搬完 97 个正好是一帧完整数据 + 复位。**整个过程 CPU 不参与**，主循环是空的。

## 现象

上电后 4 颗灯常亮红色，之后不再变化（只发了一帧）。

## 备注

- **数组必须是 `static` 或全局**。DMA 在后台持续读这块内存，局部数组出了作用域就失效，会被栈复用覆盖，表现为灯乱闪或颜色随机。
- 传参时把 `uint16_t[]` 强转成 `(uint32_t*)` 是 HAL 的惯例写法，实际按 `MemDataAlignment = HALFWORD` 处理，所以**数组元素必须是 16 位**。写成 `uint32_t` 数组会让每个元素占 4 字节、高 16 位被当成下一个比较值，波形全乱。
- **3.3 V 驱动 5 V 灯带是临界状态**：WS2812B 的 VIH 约 0.7 × VDD = 3.5 V，3.3 V 略低于它。短灯带、短线通常能用；灯多或线长时首颗灯之后容易闪烁/错色，此时加 74HCT245 电平转换，或把灯带供电降到 4.5 V。
- `WS2812.h` 里有个笔误：`#ifndef INC_WS2812_H_` 配的是 `#define INC_WS2181_H`（2181 而非 2812），**这个宏保护实际是失效的**，重复包含会重复展开。因为里面只有一个函数声明，重复声明合法，所以没出问题——但改头文件时别被它误导。
- 要做动态效果（呼吸、流水、彩虹），每次刷新前必须先 `HAL_TIM_PWM_Stop_DMA()` + `__HAL_TIM_SetCounter(&htim3, 0)`，否则第二帧的起始相位会错位。见 [`colorful-lights`](../colorful-lights)。
